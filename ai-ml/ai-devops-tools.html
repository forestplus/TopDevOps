1. Универсальные AI-ассистенты и поиск

Для анализа документации, логов, конфигураций, архитектурных решений, подготовки runbook и исследования незнакомых технологий.

General assistant

ChatGPT

Разбор инцидентов, генерация скриптов, объяснение конфигураций, анализ файлов и проектирование решений.

Research assistant

Claude

Работа с большими контекстами, ревью изменений, анализ архитектуры и технических документов.

Search / answers

Perplexity

Поиск технических решений с источниками, сравнение инструментов и быстрое исследование документации.

Multimodal assistant

Google Gemini

Анализ больших материалов, мультимодальных данных, документации и рабочих сценариев.

Knowledge research

NotebookLM

Исследование собственного набора документов, стандартов, инструкций и проектных материалов.

Model platform

OpenRouter

Единый API-доступ к разным моделям для экспериментов, маршрутизации и сравнения качества/стоимости.

AI platform

Mistral Le Chat

Альтернативный AI-ассистент и знакомство с моделями Mistral.

AI assistant

Kimi

Работа с документами, длинным контекстом и исследовательскими задачами.

AI assistant

Grok

Дополнительная модель для анализа, идей и независимой проверки гипотез.

AI ecosystem

Poe

Быстрое сравнение доступных моделей и специализированных ботов.

AI IDE

IDE assistant

Автодополнение, чат, генерация тестов и помощь при работе с кодом в IDE и GitHub.

AI IDE

AI-ориентированная среда разработки с агентным выполнением задач.

Open source agent

Cline

IDE-агент, который может исследовать проект, редактировать файлы и запускать команды с подтверждением.

Coding agent

Терминальный pair-programming инструмент с интеграцией Git и поддержкой разных LLM.

Open source

Расширение для IDE и настраиваемый AI coding workflow с выбором моделей и контекста.

AI coding agent

Claude Code

Агент для работы с репозиторием из терминала: анализ, правки, тесты и Git-операции.

AI developer platform

Replit

Создание и запуск приложений с AI-агентом и управляемой средой разработки.

8. С чего начать: приоритетный набор

Не нужно пытаться изучить всё сразу. Для DevOps-инженера полезнее освоить небольшой набор и собрать на нём законченный рабочий сценарий.

ПриоритетИнструментПрактический результат
1ChatGPT / ClaudeРазбор логов, конфигов, инцидентов и технических решений.
2Cursor или Claude CodeРабота с реальным репозиторием: анализ, изменения, тесты и ревью.
3Ollama + QwenЛокальный inference и интеграция модели через HTTP API.
4n8nАвтоматизация уведомлений, webhook и типовых операций.
5OpenAI Agents SDK или LangGraphПостроение управляемого агента с инструментами и ограничениями.
6MLflowВерсионирование экспериментов и воспроизводимость ML-процессов.
7Qdrant + RAGПоиск по внутренней технической документации и runbook.
8LangfuseТрассировка LLM-запросов, контроль стоимости и качества.
9Prometheus + GrafanaНаблюдаемость inference-сервисов и инфраструктуры.
10Docker Compose / KubernetesПовторяемое развёртывание AI-сервисов и их зависимостей.
Практический мини-проект: развернуть Ollama с небольшой Qwen-моделью, подключить Telegram-бота через FastAPI, добавить поиск по собственным runbook через Qdrant, а вызовы модели и качество ответов отслеживать в Langfuse. Это даст цельную инженерную историю: runtime → API → RAG → observability → deployment.

9. Безопасность и production-практика

  • Секреты: не отправлять в публичные модели токены, пароли, приватные ключи, kubeconfig и содержимое секретных хранилищ.
  • Данные: передавать логи и конфигурации только после удаления персональных данных, адресов, идентификаторов и секретов.
  • Доступ: AI-агенту выдавать минимально необходимые права; read-only по умолчанию.
  • Изменения: опасные операции (удаление ресурсов, изменение production, ротация секретов) выполнять только через явное подтверждение и аудит.
  • Проверка: команды, YAML, Terraform/Ansible-код и shell-скрипты проверять тестами, lint и review до применения.
  • Надёжность: учитывать rate limits, timeout, retry с backoff, стоимость токенов, fallback-модели и недоступность провайдера.
  • Локальные модели: локальный запуск сам по себе не гарантирует безопасность; ограничивать сетевой доступ, хранить данные и модели с контролем доступа.
Важно: AI — помощник, а не источник истины и не замена change management. Не передавай агенту неограниченный доступ к production-кластерам, облачным аккаунтам и системам управления секретами.
