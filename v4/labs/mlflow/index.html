LAB 01 / ML PLATFORM OPERATIONS

MLflow Tracking
with PostgreSQL.

A reproducible local stack for experiment tracking and model lifecycle exploration. Docker Compose starts MLflow and PostgreSQL; run artifacts are stored in a persistent local volume.

MLflow 2.17.2PostgreSQL 16Docker ComposeLocal artifact proxy

1. Start services

cd v4/labs/mlflow
cp .env.example .env
# Set POSTGRES_PASSWORD in .env
docker compose up -d --build
docker compose ps
docker compose logs -f mlflow

Open http://localhost:5000 after the services start. MLflow is bound to localhost; PostgreSQL is reachable only inside the Compose network.

2. Run the sample experiment

python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python experiment.py

The script creates a synthetic regression dataset, trains three Ridge models and logs parameters, metrics and model artifacts to the demo-regression experiment.

BACKEND STORE

PostgreSQL

Stores experiments, runs, parameters, metrics and model registry metadata. The database uses a named persistent volume.

ARTIFACT STORAGE

MLflow artifact proxy

Artifacts are written to a Docker volume and served through MLflow. This is convenient for a single-node lab; production should use managed object storage.

3. Operational checklist

  • Replace the example database password before use.
  • Back up PostgreSQL metadata and artifacts together; test restores.
  • Keep MLflow and PostgreSQL images pinned and upgrade deliberately.
  • Add authentication, TLS, authorization and secret management before shared use.
  • Monitor tracking-server health, request failures, database growth and artifact capacity.
  • Define model validation and promotion criteria before registering production models.
Local educational lab only. It is not hardened for production, and the synthetic dataset is only for validating the tracking workflow.
