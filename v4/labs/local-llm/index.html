LAB 02 / LOCAL INFERENCE

Local LLM runtime
with Ollama & Qwen.

A compact, Docker-based inference setup for experimenting with local language models. The default Qwen2.5 0.5B model is a deliberately small starting point for resource-constrained hardware.

OllamaQwen2.5 0.5BDockerLocal REST API

1. Start the runtime

cd v4/labs/local-llm
docker compose up -d
docker compose exec ollama ollama pull qwen2.5:0.5b
docker compose exec ollama ollama run qwen2.5:0.5b

2. Call the HTTP API

curl http://localhost:11434/api/generate -d '{
  "model": "qwen2.5:0.5b",
  "prompt": "Explain what a Kubernetes Deployment does.",
  "stream": false
}'

The service listens on 127.0.0.1:11434 only. It is not exposed to the public internet.

MODEL SELECTION

Start small

Use a small quantized model to validate the runtime and API integration. Move to larger parameter counts only after checking available RAM, CPU and expected latency.

RESOURCE MANAGEMENT

Constrained hardware

On a 4 GB RAM host, run only the inference service and a tiny model. A browser UI and multiple background services can consume the remaining memory and cause swapping.

Ollama's local API does not provide authentication by default. Keep it bound to loopback and never publish port 11434 directly to the internet. Model availability and runtime behavior depend on host architecture and memory.
