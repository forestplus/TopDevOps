1. Что такое Ansible и зачем он нужен

Представьте, что у вас 20 серверов, и на каждом нужно установить nginx, поменять один конфиг и перезапустить сервис. Зайти на каждый сервер вручную по SSH и набрать команды — это долго, и легко где-то ошибиться. Ansible делает это за вас: вы описываете, каким должен быть сервер, а Ansible сам подключается и приводит его к этому виду.

Ключевые особенности:

  • Без агентов. На управляемых серверах ничего устанавливать не нужно. Достаточно SSH и Python.
  • Понятный язык. Сценарии пишутся в YAML, его читает даже человек, далёкий от программирования.
  • Идемпотентность. Если сервер уже в нужном состоянии, Ansible ничего не меняет. Можно запускать один и тот же сценарий сколько угодно раз.
  • Огромный набор модулей. Есть готовые модули для apt, yum, docker, файлов, пользователей, облаков AWS, Azure, GCP и многого другого.
Простыми словамиAnsible — это «рецепт» для серверов. Вы пишете рецепт один раз, а потом применяете его к любому количеству машин.

2. Как устроен Ansible: главные понятия

Ansible состоит из нескольких простых частей. Их легко запомнить, если представить схему:

  • Control node — машина, с которой вы запускаете Ansible. Обычно это ваш ноутбук или отдельный сервер.
  • Managed nodes — серверы, которыми управляете. Ansible подключается к ним по SSH.
  • Inventory — список серверов с группами, например «веб-серверы» и «базы данных».
  • Module — готовое действие: установить пакет, скопировать файл, перезапустить сервис.
  • Task — один шаг, который вызывает модуль.
  • Play — набор задач для определённой группы серверов.
  • Playbook — файл с одним или несколькими play. Это главный сценарий.
  • Role — аккуратно упакованный набор задач, файлов и шаблонов, который можно переиспользовать.

3. Установка

Ansible устанавливается на control node. Серверы, которыми вы управляете, ставить ничего не нужно.

Ubuntu / Debian

sudo apt update
sudo apt install -y ansible
ansible --version

Через pip (любая система с Python)

python3 -m pip install --user ansible
ansible --version
ЛайфхакЕсли нужна свежая версия, ставьте через pip в виртуальное окружение: python3 -m venv ~/ansible-venv, затем source ~/ansible-venv/bin/activate и pip install ansible.

Подготовка SSH

Ansible работает по SSH, поэтому удобнее всего зайти на серверы по ключу, без пароля:

ssh-keygen -t ed25519
ssh-copy-id ubuntu@192.168.1.10
ssh ubuntu@192.168.1.10   # должно войти без пароля

4. Инвентарь (inventory): список ваших серверов

Инвентарь — это файл, в котором перечислены серверы и группы. Самый простой вариант — формат INI:

# inventory.ini
[webservers]
web1 ansible_host=192.168.1.10
web2 ansible_host=192.168.1.11

[dbservers]
db1 ansible_host=192.168.1.20

[all:vars]
ansible_user=ubuntu
ansible_ssh_private_key_file=~/.ssh/id_ed25519
Проверьте, что связь естьКомандой ansible all -i inventory.ini -m ping вы увидите, отвечает ли каждый сервер.

Группы и переменные в инвентаре

Один сервер может входить в несколько групп. Это удобно: например, сервер может быть и веб-сервером, и сервером мониторинга. Переменные для группы пишутся в секции [имя_группы:vars].

[production:children]
webservers
dbservers

[webservers:vars]
http_port=80

Группа production объединяет другие группы. Так удобно разделять окружения: production, staging, test.

ОсторожноНе храните пароли в открытом виде в инвентаре. Для секретов используйте ansible-vault (раздел 11).

5. Ad-hoc команды: быстрые действия в одну строку

Ad-hoc команда — это разовое действие без сценария. Например, проверить, что серверы живы, или посмотреть аптайм. Общий вид:

ansible <группа_или_хост> -i inventory.ini -m <модуль> -a "<аргументы>"

Примеры:

# Проверить связь со всеми серверами
ansible all -i inventory.ini -m ping

# Узнать время работы системы на веб-серверах
ansible webservers -i inventory.ini -m shell -a "uptime"

# Установить htop на всех серверах (с правами sudo)
ansible all -i inventory.ini -m apt -a "name=htop state=present" --become

# Перезапустить nginx только на web1
ansible web1 -i inventory.ini -m service -a "name=nginx state=restarted" --become

# Скопировать файл на все веб-серверы
ansible webservers -i inventory.ini -m copy -a "src=./index.html dest=/var/www/html/" --become

# Посмотреть факты о сервере (ОС, IP, память и т.д.)
ansible web1 -i inventory.ini -m setup | less
ЛайфхакAd-hoc удобен для разовых задач, но для всего, что нужно повторять, пишите плейбуки. Ad-hoc команду легко забыть, плейбук всегда можно открыть и посмотреть.

6. Модули: «кирпичики» Ansible

Модуль — это готовый инструмент для конкретного действия. Вы не пишете команду вида apt install nginx вручную, а вызываете модуль, который сам всё правильно сделает. Вот основные модули, которые понадобятся чаще всего:

ЗадачаМодульПример использования
Пакеты (Debian/Ubuntu)ansible.builtin.aptустановить nginx
Пакеты (RHEL/CentOS)ansible.builtin.dnfустановить httpd
Сервисыansible.builtin.serviceзапустить и включить в автозагрузку
Копирование файлаansible.builtin.copyотправить конфиг на сервер
Шаблон с переменнымиansible.builtin.templateконфиг с IP и портом из переменных
Пользователиansible.builtin.userсоздать пользователя deploy
Директории и файлыansible.builtin.fileсоздать папку, поменять права
Командыansible.builtin.command, shellвыполнить произвольную команду
Docker-контейнерыcommunity.docker.docker_containerзапустить контейнер
Лайфхак: полные имена модулей (FQCN)Всегда пишите модуль с полным именем, например ansible.builtin.apt, а не просто apt. Так код понятен и не сломается, если модуль переедет в другую коллекцию.

7. Плейбуки: сценарии автоматизации

Плейбук — это YAML-файл, в котором описано, что сделать и на каких серверах. Сначала посмотрим схему:

Первый плейбук: установка nginx

Создайте файл site.yml:

---
- name: Установить и запустить nginx
  hosts: webservers
  become: true

  tasks:
    - name: Обновить список пакетов и установить nginx
      ansible.builtin.apt:
        name: nginx
        state: present
        update_cache: true

    - name: Запустить nginx и включить автозапуск
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

Запуск:

# Сначала посмотрите, что будет изменено, ничего не меняя
ansible-playbook -i inventory.ini site.yml --check --diff

# Теперь выполните
ansible-playbook -i inventory.ini site.yml

Что значит каждая строка:

  • --- — начало YAML-файла.
  • name — понятное название. Оно выводится в консоли, поэтому пишите его так, чтобы было ясно, что происходит.
  • hosts — на каких серверах (группа из инвентаря).
  • become: true — выполнять с правами sudo.
  • tasks — список шагов.
  • state: present — пакет должен быть установлен. Если уже установлен, Ansible ничего не делает.
Ключевая идея: идемпотентностьЗапустите плейбук второй раз. Вы увидите, что задачи помечены как ok, а не changed. Это значит, что сервер уже в нужном состоянии, и Ansible ничего не трогал.

Пример: настройка сайта с шаблоном и перезапуском

---
- name: Настроить веб-сервер
  hosts: webservers
  become: true

  tasks:
    - name: Скопировать страницу сайта
      ansible.builtin.copy:
        src: files/index.html
        dest: /var/www/html/index.html
        mode: "0644"
      notify: Перезапустить nginx

  handlers:
    - name: Перезапустить nginx
      ansible.builtin.service:
        name: nginx
        state: restarted

Handler выполняется только тогда, когда задача сообщила об изменении (changed). Если файл не менялся, nginx не перезапустится. Это экономит время и не мешает работе сайта лишний раз.

Лайфхак: проверка без изменений--check показывает, что Ansible собирается сделать, но ничего не меняет. --diff дополнительно покажет, как изменится содержимое файлов. Используйте эту пару перед каждым запуском на production.

8. Переменные, условия, циклы и handlers

Переменные

Переменные позволяют не писать одно и то же значение в разных местах. Их можно задать в плейбуке, в инвентаре или в отдельных файлах.

- name: Настроить сайт
  hosts: webservers
  become: true

  vars:
    site_name: "Мой сайт"
    site_port: 8080

  tasks:
    - name: Показать значение переменной
      ansible.builtin.debug:
        msg: "Сайт {{ site_name }} будет на порту {{ site_port }}"

Двойные фигурные скобки {{ ... }} означают «подставь значение переменной».

Факты: что Ansible знает о сервере

Перед запуском задач Ansible автоматически собирает факты — информацию о сервере: ОС, версию, IP, объём памяти. Их можно использовать в условиях:

- name: Установить nginx только на Ubuntu
  ansible.builtin.apt:
    name: nginx
    state: present
  when: ansible_distribution == "Ubuntu"

Условия (when)

- name: Перезагрузить только если нужно
  ansible.builtin.reboot:
  when: kernel_updated is defined and kernel_updated

Циклы (loop)

Вместо пяти одинаковых задач можно написать одну:

- name: Установить несколько пакетов
  ansible.builtin.apt:
    name: "{{ item }}"
    state: present
  loop:
    - git
    - curl
    - htop
    - vim

Теги

Теги позволяют запускать только часть плейбука:

- name: Установить nginx
  ansible.builtin.apt:
    name: nginx
  tags: [install, nginx]
# Выполнить только задачи с тегом install
ansible-playbook -i inventory.ini site.yml --tags install

# Пропустить задачи с тегом install
ansible-playbook -i inventory.ini site.yml --skip-tags install

9. Шаблоны Jinja2

Шаблон — это файл-заготовка с переменными. Ansible подставляет туда нужные значения и отправляет готовый файл на сервер. Расширение обычно .j2.

# templates/nginx.conf.j2
server {
    listen {{ site_port }};
    server_name {{ inventory_hostname }};

    root /var/www/{{ site_name | lower | replace(' ', '-') }};
}

Задача, которая использует шаблон:

- name: Скопировать конфиг nginx
  ansible.builtin.template:
    src: templates/nginx.conf.j2
    dest: /etc/nginx/sites-available/default
  notify: Перезапустить nginx
ЛайфхакЕсли нужно вывести переменную с пустым значением по умолчанию, используйте фильтр: {{ my_var | default('значение') }}.

10. Роли: порядок в большом проекте

Когда плейбуков становится много, удобно разложить всё по ролям. Роль — это стандартная структура папок, которую Ansible понимает сам.

roles/
└── nginx/
    ├── tasks/
    │   └── main.yml        # основные задачи
    ├── handlers/
    │   └── main.yml        # обработчики (перезапуск)
    ├── templates/
    │   └── nginx.conf.j2   # шаблоны
    ├── files/
    │   └── index.html      # обычные файлы
    ├── defaults/
    │   └── main.yml        # переменные по умолчанию
    └── vars/
        └── main.yml        # переменные с высоким приоритетом

Теперь главный плейбук становится коротким:

---
- name: Настроить веб-серверы
  hosts: webservers
  become: true
  roles:
    - nginx

Создать пустую роль со всей структурой можно одной командой:

ansible-galaxy init roles/nginx
ЛайфхакНе копируйте роли вручную. Посмотрите готовые на Ansible Galaxy (ansible-galaxy search nginx) и берите за основу проверенные решения.

11. Секреты: ansible-vault

Пароли, ключи и токены нельзя хранить в открытом виде в репозитории. Ansible Vault шифрует файлы.

# Создать зашифрованный файл
ansible-vault create group_vars/all/secrets.yml

# Зашифровать существующий файл
ansible-vault encrypt secrets.yml

# Посмотреть содержимое
ansible-vault view secrets.yml

# Изменить
ansible-vault edit secrets.yml

# Запустить плейбук, который использует секреты
ansible-playbook -i inventory.ini site.yml --ask-vault-pass

Содержимое секретного файла (до шифрования):

db_password: "очень_длинный_пароль"

Чтобы пароль не попадал в логи, добавьте в задачу:

- name: Настроить базу данных
  ansible.builtin.command: "setup-db --password {{ db_password }}"
  no_log: true
ВажноФайл с паролем для vault (например, .vault_pass) не должен попадать в git. Добавьте его в .gitignore.

12. Лайфхаки

  • Ставьте --check --diff перед каждым запуском на боевых серверах. Это самая полезная привычка.
  • Используйте --limit, чтобы запускать на одном сервере: ansible-playbook site.yml --limit web1. Удобно для теста.
  • Создайте ansible.cfg в папке проекта, чтобы не писать одни и те же параметры каждый раз: 
    [defaults]
inventory = inventory.ini
forks = 20

[ssh_connection]
pipelining = True
    forks — сколько серверов обрабатывать параллельно. pipelining ускоряет SSH.
  • Проверяйте код линтером: pip install ansible-lint, затем ansible-lint site.yml. Он подскажет ошибки и плохие практики.
  • Смотрите документацию прямо в терминале: ansible-doc ansible.builtin.apt.
  • Отладка: добавьте -v, -vv или -vvv, чтобы увидеть подробности выполнения.
  • Смотрите, что знает Ansible о хосте: ansible-inventory -i inventory.ini --list.
  • Используйте debug для проверки переменных: 
    - name: Показать переменную
  ansible.builtin.debug:
    var: site_port
  • Не бойтесь повторного запуска. Идемпотентность — ваш главный друг. Плейбук можно запускать много раз подряд.

13. Частые ошибки и как их избежать

ОшибкаПочему возникаетЧто делать
UNREACHABLE! ... Permission deniedНе настроен SSH-ключ или неверный пользовательПроверьте ssh user@host вручную, поправьте ansible_user
Missing sudo passwordНужны права root, а пароль не переданДобавьте --ask-become-pass или настройте sudo без пароля для пользователя
couldn't resolve module/actionОпечатка в имени модуля или не установлена коллекцияПроверьте имя через ansible-doc, установите коллекцию через ansible-galaxy collection install
Ошибка отступов в YAMLYAML чувствителен к пробеламИспользуйте 2 пробела, не табы. Проверяйте ansible-lint
Задача всегда changedКоманда shell или command каждый раз что-то меняетИспользуйте специализированный модуль или добавьте changed_when и creates
Handler не сработалИмя в notify не совпадает с именем handlerИмена должны совпадать посимвольно
