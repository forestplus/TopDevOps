«All in One/Всё в Одном» DevOps guide. DevOps of all Commands Cheat

Linux — основа DevOps: как швейцарский нож для серверов. Git — «машина времени» для кода. Docker упаковывает приложения в переносимые контейнеры. Kubernetes управляет контейнерами в кластере, Helm устанавливает приложения в Kubernetes, а Terraform описывает инфраструктуру в виде кода.

Linux Git GitHub Docker Kubernetes Helm Terraform Примечания

1. Базовые команды Linux

  • pwd — вывести текущий рабочий каталог
  • ls — вывести список файлов и каталогов
  • cd — сменить каталог
  • touch — создать пустой файл
  • mkdir — создать каталог
  • rm — удалить файлы или каталоги
  • rmdir — удалить пустой каталог
  • cp — копировать файлы или каталоги
  • mv — переместить или переименовать файлы и каталоги
  • cat — вывести содержимое файла
  • echo — вывести строку текста
  • clear — очистить экран терминала

2. Промежуточные команды Linux

  • chmod — изменить права доступа к файлам
  • chown — изменить владельца файла
  • find — искать файлы и каталоги
  • grep — искать текст в файле
  • wc — подсчитать строки, слова и символы
  • head — вывести первые строки файла
  • tail — вывести последние строки файла
  • sort — отсортировать содержимое файла
  • uniq — удалить повторяющиеся строки
  • diff — построчно сравнить два файла
  • tar — упаковать файлы в архив tar
  • zip/unzip — сжать и распаковать ZIP-файлы
  • df — показать использование дискового пространства
  • du — показать размер каталога
  • top — отслеживать процессы в реальном времени
  • ps — показать активные процессы
  • kill — завершить процесс по PID
  • ping — проверить сетевое соединение
  • wget — скачать файлы из интернета
  • curl — передать данные на сервер или с сервера
  • scp — безопасно копировать файлы между системами
  • rsync — синхронизировать файлы и каталоги

3. Продвинутые команды Linux

  • awk — обработка текста и поиск по шаблону
  • sed — потоковый редактор для фильтрации и преобразования текста

  • iostat — статистика CPU и ввода-вывода
  • netstat — сетевая статистика (современная замена: ss)
  • ifconfig/ip — настройка сетевых интерфейсов (современная замена: ip)
  • iptables — настройка правил файрвола

  • journalctl — просмотр системных логов

  • whoami — показать текущего пользователя

  • env — показать переменные окружения

11. Git: основы

Git — «машина времени» для кода: отслеживает изменения, помогает работать в команде без конфликтов и откатывать ошибки.

  • git init — инициализирует новый репозиторий в текущем каталогеПример: git init
  • git clone — копирует удалённый репозиторий на локальную машинуПример: git clone https://github.com/user/repo.git
  • git status — состояние рабочего каталога и области подготовкиПример: git status
  • git add — добавляет изменения в область подготовкиПример: git add file.txt
  • git commit — фиксирует изменения в репозиторииПример: git commit -m "Initial commit"
  • git config — настройки пользователя, например имя и emailПример: git config --global user.name "Your Name"
  • git log — история коммитовПример: git log
  • git show — подробная информация о коммитеПример: git show <commit-hash>
  • git diff — изменения между коммитами, рабочим каталогом и областью подготовкиПример: git diff
  • git reset — убирает файлы из области подготовки или откатывает коммитыПример: git reset HEAD file.txt

12. Ветки и слияние

  • git branch — список веток или создание новойПример: git branch feature-branch
  • git checkout — переключение веток или восстановление файловПример: git checkout feature-branch
  • git switch — переключение веток (современная замена checkout)Пример: git switch feature-branch
  • git merge — объединяет изменения из одной ветки в другуюПример: git merge feature-branch
  • git rebase — переносит коммиты одной ветки поверх другойПример: git rebase main
  • git cherry-pick — применяет отдельный коммит из одной ветки в другуюПример: git cherry-pick <commit-hash>

13. Удалённые репозитории

  • git remote — управление подключениями к удалённым репозиториямПример: git remote add origin https://github.com/user/repo.git
  • git push — отправляет изменения в удалённый репозиторийПример: git push origin main
  • git pull — получает и объединяет изменения из удалённого репозиторияПример: git pull origin main
  • git fetch — загружает изменения без слиянияПример: git fetch origin
  • git remote -v — список URL удалённых репозиториевПример: git remote -v

14. Stash и очистка

  • git stash — временно сохраняет незафиксированные измененияПример: git stash
  • git stash pop — применяет сохранённые изменения и удаляет их из спискаПример: git stash pop
  • git stash list — список всех stashПример: git stash list
  • git clean — удаляет неотслеживаемые файлы из рабочего каталогаПример: git clean -f

15. Теги

  • git tag — создаёт тег для коммитаПример: git tag -a v1.0 -m "Version 1.0"
  • git tag -d — удаляет тегПример: git tag -d v1.0
  • git push --tags — отправляет теги в удалённый репозиторийПример: git push origin --tags

16. Продвинутые команды Git

  • git bisect — находит коммит, который внёс ошибкуПример: git bisect start
  • git blame — показывает коммит и автора каждой строки файлаПример: git blame file.txt
  • git reflog — журнал изменений вершин ветокПример: git reflog
  • git submodule — внешние репозитории как подмодулиПример: git submodule add https://github.com/user/repo.git
  • git archive — архив файлов репозиторияПример: git archive --format=zip HEAD > archive.zip
  • git gc — очистка ненужных файлов и оптимизация репозиторияПример: git gc

17. Команды GitHub (gh CLI)

  • gh auth login — вход в GitHub через командную строкуПример: gh auth login
  • gh repo clone — клонирование репозитория GitHubПример: gh repo clone user/repo
  • gh issue list — список задач (issues) в репозиторииПример: gh issue list
  • gh pr create — создание pull requestПример: gh pr create --title "New Feature" --body "Description of the feature"
  • gh repo create — создание нового репозитория на GitHubПример: gh repo create my-repo

18. Docker: основы

Docker упаковывает приложения в переносимые контейнеры — как транспортные контейнеры для софта. Команды помогают собирать, отправлять и запускать приложения одинаково в любой среде.

  • docker --version — версия установленного DockerПример: docker --version
  • docker info — общая информация о Docker: количество контейнеров и образовПример: docker info
  • docker pull — загрузка образа из реестра (по умолчанию Docker Hub)Пример: docker pull ubuntu:latest
  • docker images — список загруженных образовПример: docker images
  • docker run — создаёт и запускает контейнер из образаПример: docker run -it ubuntu bash
  • docker ps — список запущенных контейнеровПример: docker ps
  • docker ps -a — все контейнеры, включая остановленныеПример: docker ps -a
  • docker stop — остановка запущенного контейнераПример: docker stop container_name
  • docker start — запуск остановленного контейнераПример: docker start container_name
  • docker rm — удаление контейнераПример: docker rm container_name
  • docker rmi — удаление образаПример: docker rmi image_name
  • docker exec — выполнение команды в запущенном контейнереПример: docker exec -it container_name bash

19. Docker: промежуточный уровень

  • docker build — сборка образа из DockerfileПример: docker build -t my_image .
  • docker commit — создание образа из изменений контейнераПример: docker commit container_name my_image:tag
  • docker logs — логи контейнераПример: docker logs container_name
  • docker inspect — подробная информация об объекте (контейнере или образе)Пример: docker inspect container_name
  • docker stats — статистика потребления ресурсов запущенными контейнерами в реальном времениПример: docker stats
  • docker cp — копирование файлов между контейнером и хостомПример: docker cp container_name:/path/in/container /path/on/host
  • docker rename — переименование контейнераПример: docker rename old_name new_name
  • docker network ls — список сетей DockerПример: docker network ls
  • docker network create — создание сетиПример: docker network create my_network
  • docker network inspect — подробности о сетиПример: docker network inspect my_network
  • docker network connect — подключение контейнера к сетиПример: docker network connect my_network container_name
  • docker volume ls — список томовПример: docker volume ls
  • docker volume create — создание томаПример: docker volume create my_volume
  • docker volume inspect — подробности о томеПример: docker volume inspect my_volume
  • docker volume rm — удаление томаПример: docker volume rm my_volume

20. Docker: продвинутые команды, Compose и Swarm

  • docker-compose up — запуск сервисов из docker-compose.ymlПример: docker-compose up
  • docker-compose down — остановка и удаление сервисов из docker-compose.ymlПример: docker-compose down
  • docker-compose logs — логи сервисов ComposeПример: docker-compose logs
  • docker-compose exec — выполнение команды в контейнере сервисаПример: docker-compose exec service_name bash
  • docker save — экспорт образа в tar-файлПример: docker save -o my_image.tar my_image:tag
  • docker load — импорт образа из tar-файлаПример: docker load < my_image.tar
  • docker export — экспорт файловой системы контейнера в tar-файлПример: docker export container_name > container.tar
  • docker import — создание образа из экспортированного контейнераПример: docker import container.tar my_new_image
  • docker system df — использование диска объектами DockerПример: docker system df
  • docker system prune — очистка неиспользуемых ресурсов (образов, контейнеров, томов, сетей)Пример: docker system prune
  • docker tag — присвоение образу нового тегаПример: docker tag old_image_name new_image_name
  • docker push — загрузка образа в реестрПример: docker push my_image:tag
  • docker login / docker logout — вход и выход из реестраПример: docker login, docker logout
  • docker swarm init — инициализация кластера Docker SwarmПример: docker swarm init
  • docker service create — создание сервиса в режиме SwarmПример: docker service create --name my_service nginx
  • docker stack deploy — развёртывание стека из Compose-файла в SwarmПример: docker stack deploy -c docker-compose.yml my_stack
  • docker stack rm — удаление стека в SwarmПример: docker stack rm my_stack
  • docker checkpoint create / ls / rm — создание, список и удаление чекпоинтов контейнераПример: docker checkpoint create container_name checkpoint_name

21. Kubernetes: основы

Kubernetes — «дирижёр» контейнерного оркестра: автоматизирует развёртывание, масштабирование и управление приложениями в кластере серверов.

  • kubectl version — версия клиента и сервераПример: kubectl version --short
  • kubectl cluster-info — информация о кластереПример: kubectl cluster-info
  • kubectl get nodes — список узлов кластераПример: kubectl get nodes
  • kubectl get pods — список подов в namespace defaultПример: kubectl get pods
  • kubectl get services — список сервисов в namespace defaultПример: kubectl get services
  • kubectl get namespaces — список namespace в кластереПример: kubectl get namespaces
  • kubectl describe pod — подробная информация о подеПример: kubectl describe pod pod-name
  • kubectl logs — логи подаПример: kubectl logs pod-name
  • kubectl create namespace — создание namespaceПример: kubectl create namespace my-namespace
  • kubectl delete pod — удаление подаПример: kubectl delete pod pod-name

22. Kubernetes: промежуточный уровень

  • kubectl apply — применить изменения из YAML-файлаПример: kubectl apply -f deployment.yaml
  • kubectl delete — удалить ресурсы из YAML-файлаПример: kubectl delete -f deployment.yaml
  • kubectl scale — масштабировать деплоймент до нужного числа репликПример: kubectl scale deployment my-deployment --replicas=3
  • kubectl expose — открыть под или деплоймент как сервисПример: kubectl expose deployment my-deployment --type=LoadBalancer --port=80
  • kubectl exec — выполнить команду в запущенном подеПример: kubectl exec -it pod-name -- /bin/bash
  • kubectl port-forward — пробросить локальный порт на порт подаПример: kubectl port-forward pod-name 8080:80
  • kubectl get configmaps — список ConfigMapПример: kubectl get configmaps
  • kubectl get secrets — список SecretПример: kubectl get secrets
  • kubectl edit — редактирование ресурса прямо в редактореПример: kubectl edit deployment my-deployment
  • kubectl rollout status — статус обновления деплойментаПример: kubectl rollout status deployment/my-deployment

23. Kubernetes: продвинутые команды

  • kubectl rollout undo — откат деплоймента к предыдущей ревизииПример: kubectl rollout undo deployment/my-deployment
  • kubectl top nodes / pods — использование ресурсов узлами и подамиПример: kubectl top pods
  • kubectl cordon — пометить узел как недоступный для планированияПример: kubectl cordon node-name
  • kubectl uncordon — снова разрешить планирование на узлеПример: kubectl uncordon node-name
  • kubectl drain — безопасно вытеснить поды с узлаПример: kubectl drain node-name --ignore-daemonsets
  • kubectl taint — добавить taint на узел для управления размещением подовПример: kubectl taint nodes node-name key=value:NoSchedule
  • kubectl get events — все события в кластереПример: kubectl get events
  • kubectl apply -k — применить ресурсы из каталога kustomizationПример: kubectl apply -k ./kustomization-dir/
  • kubectl config view — показать kubeconfigПример: kubectl config view
  • kubectl config use-context — переключить активный контекстПример: kubectl config use-context my-cluster
  • kubectl debug — создать сессию отладки для подаПример: kubectl debug pod-name
  • kubectl delete namespace — удалить namespace и его ресурсыПример: kubectl delete namespace my-namespace
  • kubectl patch — обновить ресурс с помощью patchПример: kubectl patch deployment my-deployment -p '{"spec": {"replicas": 2}}'
  • kubectl rollout history — история ревизий деплойментаПример: kubectl rollout history deployment my-deployment
  • kubectl autoscale — автоматическое масштабирование по использованию ресурсовПример: kubectl autoscale deployment my-deployment --cpu-percent=50 --min=1 --max=10
  • kubectl label — добавить или изменить метку ресурсаПример: kubectl label pod pod-name environment=production
  • kubectl annotate — добавить или изменить аннотацию ресурсаПример: kubectl annotate pod pod-name description="My app pod"
  • kubectl delete pv — удалить PersistentVolumeПример: kubectl delete pv my-pv
  • kubectl get ingress — список Ingress в namespaceПример: kubectl get ingress
  • kubectl create configmap — создать ConfigMapПример: kubectl create configmap my-config --from-literal=key1=value1
  • kubectl create secret — создать SecretПример: kubectl create secret generic my-secret --from-literal=password=myPassword
  • kubectl api-resources — список ресурсов API в кластереПример: kubectl api-resources
  • kubectl api-versions — список поддерживаемых версий APIПример: kubectl api-versions
  • kubectl get crds — список CustomResourceDefinition (CRD)Пример: kubectl get crds

24. Helm: основы и работа с репозиториями

Helm — «магазин приложений» для Kubernetes: устанавливает и обновляет сложные приложения из готовых пакетов («чартов») — примерно как apt-get для Kubernetes.

  • helm help — справка по Helm CLI или по конкретной командеПример: helm help
  • helm version — версия клиента и сервера HelmПример: helm version
  • helm repo add — добавить репозиторий чартовПример: helm repo add stable https://charts.helm.sh/stable
  • helm repo update — обновить все репозитории чартов до последней версииПример: helm repo update
  • helm repo list — список добавленных репозиториевПример: helm repo list
  • helm search hub — поиск чартов в Helm HubПример: helm search hub nginx
  • helm search repo — поиск чартов в репозиторияхПример: helm search repo stable/nginx
  • helm show chart — метаданные и зависимости чартаПример: helm show chart stable/nginx

25. Helm: установка и обновление чартов

  • helm install — установка чарта в кластерПример: helm install my-release stable/nginx
  • helm upgrade — обновление релиза до новой версии чартаПример: helm upgrade my-release stable/nginx
  • helm upgrade --install — установить, если нет, или обновить, если уже естьПример: helm upgrade --install my-release stable/nginx
  • helm uninstall — удалить релизПример: helm uninstall my-release
  • helm list — список релизов в кластереПример: helm list
  • helm status — статус релизаПример: helm status my-release

26. Helm: работа с чартами

  • helm create — создать новый чарт в каталогеПример: helm create my-chart
  • helm lint — проверка чарта на типичные ошибкиПример: helm lint ./my-chart
  • helm package — упаковка чарта в .tgzПример: helm package ./my-chart
  • helm template — отрисовка YAML-манифестов без установкиПример: helm template my-release ./my-chart
  • helm dependency update — обновить зависимости из Chart.yamlПример: helm dependency update ./my-chart

27. Helm: откаты, история и получение данных релиза

  • helm rollback — откат релиза к предыдущей версииПример: helm rollback my-release 1
  • helm history — история релизаПример: helm history my-release
  • helm get all — вся информация о релизе (values и шаблоны)Пример: helm get all my-release
  • helm get values — значения, использованные в релизеПример: helm get values my-release
  • helm test — запуск тестов чартаПример: helm test my-release

28. Helm: репозитории чартов

  • helm repo remove — удалить репозиторий чартовПример: helm repo remove stable
  • helm repo index — создать или обновить index-файл репозиторияПример: helm repo index ./charts

29. Helm: значения и настройка

  • helm install --values — установка с пользовательскими значениями из файлаПример: helm install my-release stable/nginx --values values.yaml
  • helm upgrade --values — обновление с пользовательскими значениямиПример: helm upgrade my-release stable/nginx --values values.yaml
  • helm install --set — установка с заданием значения прямо в командеПример: helm install my-release stable/nginx --set replicaCount=3
  • helm upgrade --set — обновление с заданием значения в командеПример: helm upgrade my-release stable/nginx --set replicaCount=5
  • helm uninstall --purge — удалить релиз вместе с ресурсами и историейПример: helm uninstall my-release --purge

30. Helm: отладка и dry-run

  • helm template --debug — отрисовка манифестов с отладочным выводомПример: helm template my-release ./my-chart --debug
  • helm install --dry-run — имитация установки без её выполненияПример: helm install my-release stable/nginx --dry-run
  • helm upgrade --dry-run — имитация обновления без его примененияПример: helm upgrade my-release stable/nginx --dry-run

31. Helm и namespace Kubernetes

  • helm list --namespace — релизы в конкретном namespaceПример: helm list --namespace kube-system
  • helm uninstall --namespace — удалить релиз из namespaceПример: helm uninstall my-release --namespace kube-system
  • helm install --namespace — установить чарт в namespaceПример: helm install my-release stable/nginx --namespace mynamespace
  • helm upgrade --namespace — обновить релиз в namespaceПример: helm upgrade my-release stable/nginx --namespace mynamespace
  • helm list -n — то же, что --namespace, в короткой формеПример: helm list -n kube-system
  • helm install / upgrade --kube-context — работа с конкретным контекстом kubeconfigПример: helm install my-release stable/nginx --kube-context my-cluster

32. Helm: разработка чартов

  • helm create --starter — создание чарта на основе стартового шаблонаПример: helm create --starter https://github.com/helm/charts.git
  • helm push — отправка чарта в репозиторийПример: helm push ./my-chart my-repo

33. Helm: зависимости и история

  • helm dependency build — сборка зависимостей чартаПример: helm dependency build ./my-chart
  • helm dependency list — список зависимостей чартаПример: helm dependency list ./my-chart

  • helm history --max — ограничить число версий в историиПример: helm history my-release --max 5

34. Terraform: основы

Terraform позволяет описывать облачную инфраструктуру кодом. Вместо кликов в консолях AWS, GCP или Azure вы описываете серверы и сервисы в конфигурационных файлах.

  • terraform --help — общая справка по командам Terraform CLI
  • terraform init — инициализирует рабочий каталог с конфигурацией и загружает плагины провайдеров
  • terraform validate — проверка конфигурационных файлов на синтаксические ошибки
  • terraform plan — создаёт план: какие действия выполнит Terraform, чтобы инфраструктура соответствовала конфигурации
  • terraform apply — применяет изменения для достижения желаемого состояния; перед изменениями запрашивает подтверждение
  • terraform show — выводит состояние или план в удобочитаемом виде
  • terraform output — выводит значения output после apply
  • terraform destroy — уничтожает инфраструктуру из конфигурации; запрашивает подтверждение
  • terraform refresh — обновляет файл состояния по реальной инфраструктуре без применения изменений
  • terraform taint — помечает ресурс для пересоздания при следующем apply, даже если он не менялся
  • terraform untaint — снимает пометку «tainted» с ресурса
  • terraform state — управление файлом состояния, например перенос ресурсов между модулями
  • terraform import — импорт существующей инфраструктуры под управление Terraform
  • terraform graph — графическое представление ресурсов и их связей
  • terraform providers — список провайдеров для текущей конфигурации
  • terraform state list — список ресурсов в файле состояния
  • terraform backend — настройка бэкенда для удалённого хранения состояния (например, S3 или Azure Blob Storage)

Примечания

Некоторые команды в исходной шпаргалке устарели или дублируются: uptime, alias и helm repo update встречаются дважды.
helm uninstall --purge — флаг из Helm 2. В Helm 3 helm uninstall по умолчанию удаляет и историю релиза; чтобы её сохранить, используйте --keep-history.
Репозиторий charts.helm.sh/stable из примеров Helm устарел; современные чарты берите из отдельных репозиториев (например, Bitnami).
netstat и ifconfig заменены на ss и ip. В Docker docker-compose (v1) заменён на docker compose (v2).
terraform backend — не отдельная команда: бэкенд задаётся в блоке terraform {} конфигурации, а terraform init его подключает.
